Day 050 — Production Sklearn Pipelines & Custom Transformers

Preventing Training-Serving Skew & Data Leakage with Custom Estimators

💡 1. Intuition & Real-World Problem Analogy

In machine learning engineering, transitioning from Jupyter notebooks to production REST APIs (FastAPI/Flask) is where most projects fail due to Training-Serving Skew and Data Leakage.

🚰 The Analogy — Industrial Water Purification Plant

  • Without Pipelines: You clean river water in bucket A, test pH in bucket B, add chlorine in bucket C. When deploying to the city supply, you attempt to repeat all manual steps. If someone skips bucket B, contaminated water flows to citizens!
  • With Scikit-Learn Pipeline: You construct a single sealed purification pipe. Dirty water goes in at one end; purified water comes out at the other. The pipe remembers exact calibration parameters.

Data Leakage Prevention Mechanism: If you run StandardScaler().fit_transform(X) on your entire dataset before splitting into train/test, the scaler learns the mean $\mu_{\text{total}}$ and variance $\sigma^2_{\text{total}}$ of test data! Using Pipeline.fit(X_train, y_train) guarantees transformations are computed strictly inside fold splits.

📐 2. Mathematical Formulation & Architecture

To integrate into Scikit-Learn's ecosystem, custom classes must inherit from two base classes:

Inheritance Architecture
$$\text{CustomTransformer} \in \text{BaseEstimator} \times \text{TransformerMixin}$$

1. BaseEstimator: Grants automated get_params() and set_params() for GridSearchCV & Optuna integration.

2. TransformerMixin: Automatically synthesizes fit_transform(X, y) by chaining fit(X, y) followed by transform(X).

IQR Outlier Clipping Formula
$$\text{Q25} = \text{Percentile}(x, 25), \quad \text{Q75} = \text{Percentile}(x, 75)$$ $$\text{IQR} = \text{Q75} - \text{Q25}$$ $$\text{Lower Bound} = \text{Q25} - c \cdot \text{IQR}, \quad \text{Upper Bound} = \text{Q75} + c \cdot \text{IQR}$$ $$\hat{x}_i = \min\left(\max\left(x_i, \text{Lower Bound}\right), \text{Upper Bound}\right)$$
💻 3. Step-by-Step Production Python Implementation
050_production_pipeline.py 
import numpy as np
import pandas as pd
import joblib
from sklearn.base import BaseEstimator, TransformerMixin
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split, cross_val_score

# 1. Custom Transformer for IQR Outlier Clipping
class IQROutlierClipper(BaseEstimator, TransformerMixin):
    def __init__(self, factor=1.5):
        self.factor = factor
        self.lower_bounds_ = {}
        self.upper_bounds_ = {}

    def fit(self, X, y=None):
        X_df = pd.DataFrame(X)
        for col in X_df.columns:
            q25 = X_df[col].quantile(0.25)
            q75 = X_df[col].quantile(0.75)
            iqr = q75 - q25
            self.lower_bounds_[col] = q25 - self.factor * iqr
            self.upper_bounds_[col] = q75 + self.factor * iqr
        return self

    def transform(self, X):
        X_df = pd.DataFrame(X).copy()
        for col in X_df.columns:
            X_df[col] = X_df[col].clip(
                lower=self.lower_bounds_[col], 
                upper=self.upper_bounds_[col]
            )
        return X_df.values

# 2. Build Sub-Pipelines & Full Pipeline
numeric_features = ['age', 'income', 'credit_score']
categorical_features = ['education', 'city']

num_pipeline = Pipeline([
    ('imputer', SimpleImputer(strategy='median')),
    ('clipper', IQROutlierClipper(factor=1.5)),
    ('scaler', StandardScaler())
])

cat_pipeline = Pipeline([
    ('imputer', SimpleImputer(strategy='most_frequent')),
    ('encoder', OneHotEncoder(handle_unknown='ignore', sparse_output=False))
])

preprocessor = ColumnTransformer([
    ('num', num_pipeline, numeric_features),
    ('cat', cat_pipeline, categorical_features)
])

full_pipeline = Pipeline([
    ('preprocessor', preprocessor),
    ('classifier', RandomForestClassifier(n_estimators=100, random_state=42))
])

# 3. Model Training, CV & Serialization

Day 051 — Imbalanced Learning (SMOTE, ADASYN, Tomek Links)

Overcoming the Accuracy Paradox in High-Skew Datasets

💡 1. Intuition & Real-World Problem Analogy

⚠️ The Accuracy Paradox

In credit card fraud detection with 99,900 legitimate transactions (Class 0) and 100 fraudulent transactions (Class 1), a dummy model predicting "All transactions are normal" scores 99.9% Accuracy, but catches 0% of fraud, causing millions in losses!

Resampling Strategies:

  • class_weight='balanced': Penalizes minority misclassification proportionally in the loss function without modifying data length.
  • SMOTE: Creates synthetic samples along line segments connecting k-nearest minority neighbors.
  • ADASYN: Focuses synthetic generation in dense boundary regions where classes overlap.
  • Tomek Links: Removes majority points from opposite-class nearest-neighbor pairs to clean noisy decision boundaries.
📐 2. Mathematical Formulations
Cost-Sensitive Class Loss Multiplier
$$w_j = \frac{N}{C \times N_j}$$

For 95% Class 0 ($N_0 = 950$) and 5% Class 1 ($N_1 = 50$):

$$w_0 = \frac{1000}{2 \times 950} \approx 0.526, \quad w_1 = \frac{1000}{2 \times 50} = 10.0$$
SMOTE Synthetic Point Generation
$$x_{\text{new}} = x_i + \lambda (x_{zi} - x_i) \quad \text{where } \lambda \sim U(0, 1)$$

🚨 Critical Pipeline Gotcha

Standard sklearn.pipeline.Pipeline cannot modify sample lengths during fit(). You MUST use imblearn.pipeline.Pipeline when incorporating SMOTE or Tomek Links!

💻 3. Resampling Pipeline Code & Visual Comparison
051_imbalanced_learning.py 
from imblearn.over_sampling import SMOTE
from imblearn.under_sampling import TomekLinks
from imblearn.combine import SMOTETomek
from imblearn.pipeline import Pipeline as ImbPipeline
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler

# Imbalanced Pipeline with SMOTE + Tomek Links
imb_pipeline = ImbPipeline(steps=[
    ('scaler', StandardScaler()),
    ('resample', SMOTETomek(smote=SMOTE(k_neighbors=5, random_state=42), tomek=TomekLinks())),
    ('classifier', LogisticRegression(random_state=42))
])

imb_pipeline.fit(X_train, y_train)
preds = imb_pipeline.predict(X_test)

Day 052 — Threshold Tuning & Probability Calibration

Aligning Model Confidence with Real-World Decision Boundaries

💡 1. Intuition & Weather Forecaster Analogy

Imagine a forecaster stating "80% chance of rain". If it rains on 80 out of 100 days when this forecast is given, the model is well-calibrated. Tree ensembles (Random Forest, XGBoost) yield distorted probabilities clustered away from 0 and 1.

Threshold Tuning: Default .predict() uses $T = 0.5$. In healthcare, missing a tumor (False Negative) is disastrous! We tune $T$ to maximize $F_1$ or custom business profit functions.

📐 2. Mathematical Formulations
Brier Score Loss Formula
$$\text{BS} = \frac{1}{N} \sum_{i=1}^N (p_i - y_i)^2$$
Platt Scaling (Sigmoid Method)
$$\hat{P}(y=1 \mid x) = \frac{1}{1 + \exp(A \cdot f(x) + B)}$$
Optimal Threshold Cutoff
$$T^* = \arg\max_T F_1(T) = \arg\max_T \frac{2 \cdot P(T) \cdot R(T)}{P(T) + R(T)}$$

Day 053 — Model Interpretability & XAI (SHAP & LIME)

Unveiling Black-Box Machine Learning Decisions

💡 1. Intuition & Legal Regulatory Framework

Under GDPR and banking regulations, financial institutions cannot reject loans without specific explanations. SHAP calculates exact fair contributions based on cooperative game theory, while LIME fits a local linear surrogate model around a single prediction point.

📐 2. Shapley Value Formulation & Additive Property
Shapley Value Equation
$$\phi_i(v) = \sum_{S \subseteq N \setminus \{i\}} \frac{|S|!(|N|-|S|-1)!}{|N|!} \left( v(S \cup \{i\}) - v(S) \right)$$
Additive Efficiency Property
$$\hat{f}(x) = E[f(x)] + \sum_{j=1}^M \phi_j(x)$$

The total model prediction equals base expected value plus the sum of all individual feature SHAP contributions!

Day 054 — Anomaly & Outlier Detection

Isolation Forest, Local Outlier Factor (LOF) & One-Class SVM

💡 1. Intuition & Algorithm Comparison

In network security and fraud detection, anomaly labels are rare or absent. Algorithms must isolate low-density instances without supervision.

  • Isolation Forest: Randomly partitions feature space. Anomalies isolate early near tree roots (short path length).
  • LOF: Compares local density relative to k-nearest neighbors. Great for multi-density clusters.
  • One-Class SVM: Constructs a hyper-sphere boundary surrounding normal points in high-dimensional kernel space.
📐 2. Isolation Forest Anomaly Score Formula
Anomaly Score Equation
$$s(x, n) = 2^{-\frac{E(h(x))}{c(n)}}$$ $$c(n) = 2 \ln(n - 1) + 0.5772156649 - \frac{2(n - 1)}{n}$$

If $E(h(x)) \to 0 \implies s \to 1.0$ (Flagged as Anomaly). If $E(h(x)) \to c(n) \implies s \to 0.5$ (Normal Instance).

Day 056 — Advanced ML Assessment, Derivations & Interview Prep

Mathematical Proofs for XGBoost Optimal Weights & Similarity Scores

🧠 1. Mathematical Derivation: XGBoost Optimal Leaf Weight ($w^*$)

The regularized objective at step $t$ using 2nd Order Taylor expansion:

$$\mathcal{L}^{(t)} \approx \sum_{i=1}^n \left[ g_i w_{q(x_i)} + \frac{1}{2} h_i w_{q(x_i)}^2 \right] + \gamma T + \frac{1}{2} \lambda \sum_{j=1}^T w_j^2$$

Group by leaf instance set $I_j = \{i \mid q(x_i) = j\}$:

$$\mathcal{L}^{(t)} = \sum_{j=1}^T \left[ \left(\sum_{i \in I_j} g_i\right) w_j + \frac{1}{2} \left(\sum_{i \in I_j} h_i + \lambda\right) w_j^2 \right] + \gamma T$$

Let $G_j = \sum_{i \in I_j} g_i$ and $H_j = \sum_{i \in I_j} h_i$. Differentiating w.r.t $w_j$ and setting to zero:

$$\frac{\partial \mathcal{L}}{\partial w_j} = G_j + (H_j + \lambda) w_j = 0 \implies w^*_j = -\frac{G_j}{H_j + \lambda}$$

Plugging $w^*_j$ back yields the Leaf Similarity Score:

$$S_j = -\frac{1}{2} \frac{G_j^2}{H_j + \lambda}$$
